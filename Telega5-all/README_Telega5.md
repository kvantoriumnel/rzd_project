# Telega5 — общая прошивка ESP32 «Аргус-01»

Одна плата ESP32 вместо двух: управление тележками (бывший `Telega4.ino` v4) и узел датчиков (бывший `sensor_node_esp32.ino` v3).
Логика обоих скетчей перенесена без изменений, кроме перечисленного в разделе «Что изменилось».

## Модули

Папка скетча должна называться `Telega5` — так требует Arduino IDE. Все файлы открываются в ней вкладками.

| Файл | Что внутри | Откуда |
|---|---|---|
| `Telega5.ino` | `setup()` и `loop()`, порядок запуска | новое |
| `config.h` | все выводы и общие константы | оба скетча |
| `motion.h/.cpp` | плата гироскутера (UART2), режимы STOP / COM / RC / AUTO / CALIB / CAL_DIST, одометрия, калибровки, настройки в NVS `hb` | Telega4 |
| `rc.h/.cpp` | приёмник RC: стик и два тумблера | Telega4 |
| `ultrasonic.h/.cpp` | 2 × HC-SR04, события STOP / CLEAR / LOST | sensor_node |
| `imu.h/.cpp` | 2 × MPU-6050, поток `I`, калибровка (NVS `imu`) | sensor_node |
| `tof.h/.cpp` | 4 × VL53L1X, поток `T` | sensor_node |
| `commands.h/.cpp` | приём и разбор команд из USB Serial | оба скетча |

Библиотеки: `hoverserial` (та же, что в Telega4) и `VL53L1X` от Pololu; `Wire` и `Preferences` входят в ядро ESP32.
Плата: **ESP32 Dev Module**, монитор порта 115200.

## Выводы

| GPIO | Назначение | Примечание |
|---|---|---|
| 16 / 17 | UART2 RX / TX — плата гироскутера | как в Telega4 |
| 23 | RC: стик | как в Telega4 |
| 15 | RC: тумблер 1 (ручное управление) | как в Telega4 |
| 2 | RC: тумблер 2 (авто) | как в Telega4 |
| 22 / 21 | I2C SDA / SCL, 100 кГц | **как в коде** sensor_node (в его шапке указано наоборот) |
| **18** | HC-SR04 A TRIG | **перенесено с GPIO 2** — он занят тумблером 2 |
| 26 | HC-SR04 A ECHO | через делитель 1к/2к |
| 25 | HC-SR04 B TRIG | |
| 34 | HC-SR04 B ECHO | через делитель 1к/2к |
| 27 | индикатор «препятствие» (HIGH) | теперь только светодиод / внешний выход |
| 33 / 4 | XSHUT дальномеров H A / H B | |
| 13 / 32 | XSHUT дальномеров G A / G B | |

**Перепайка одна:** провод TRIG ультразвукового датчика A переносится с GPIO 2 на GPIO 18.
Если плата не прошивается при подключённом приёмнике RC, отключите его на время прошивки: GPIO 2 участвует в выборе режима загрузки.

## Команды (USB Serial, 115200)

В двух скетчах одни и те же буквы значили разное: C, S, M, K, R, D. Поэтому команды датчиков теперь идут **с префиксом `N`**.

**Движение** — команды как в Telega4, без префикса:

| Команда | Действие |
|---|---|
| `STOP` | остановка |
| `S <скорость>` | движение с заданной скоростью (режим COM) |
| `A <скорость>` | скорость автоматического режима, 200…1000 |
| `M <мм>` | шаг одометрии для «Take photo» |
| `D <мм>` | диаметр колеса |
| `R <обороты> [скорость]`, `KR <обороты>`, `K <коэффициент>` | калибровка по оборотам |
| `RESET` | сброс пройденного пути |
| `C START [скорость]` / `C STOP <мм>` / `C ZERO` / `C RESET` / `C INFO` | калибровка по расстоянию |
| `HOLD 1` / `HOLD 0` | **новое:** остановка по препятствию вкл / выкл (по умолчанию вкл) |
| `O 1` / `O 0` | **новое:** поток одометрии `O` вкл / выкл (по умолчанию вкл) |

**Датчики** — бывшие команды sensor_node с префиксом `N` (пробел после N необязателен):

| Команда | Действие |
|---|---|
| `N ?` | статус датчиков |
| `N C` | калибровка IMU, 2 с, тележка останавливается |
| `N Z` | сброс калибровки IMU |
| `N Q0` / `N Q1` | поток IMU выкл / вкл |
| `N D0` / `N D1` | поток дальномеров выкл / вкл |
| `N X` | перезапуск дальномеров, тележка останавливается |
| `N S<мм>` | порог остановки |
| `N H<мм>` | гистерезис |
| `N M<мм>` | максимальная дальность |
| `N K<мм>` | порог потери цели (0 — выкл) |
| `N R` | снять LOST |
| `N T<°C>` | температура воздуха |

`?` — общий статус движения и всех датчиков.

## Вывод

Все строки от обоих скетчей сохранены в прежнем формате:
- `I` — IMU;
- `U` — ультразвук;
- `T` — дальномеры;
- `E` — события;
- `#` — служебные;
- `[РЕЖИМ] …` — состояние раз в 0,5 с;
- `Take photo #… | Distance=…` — по шагу одометрии.

Новые строки:
- `O,<мс>,<режим>,<путь мм>,<скорость мм/с>` — одометрия, 10 раз в секунду. Время общее с `T`, `I`, `U`, поэтому показания датчиков привязываются к пройденному пути;
- `E,<мс>,M,HOLD,1` и `E,<мс>,M,GO,0` — тележка остановлена препятствием и поехала дальше.

## Что изменилось при объединении

1. `delay(10)` из Telega4 убран. Такт управления по-прежнему 10 мс, но не блокирует программу, и датчики опрашиваются между тактами.
2. Если связи с платой гироскутера нет, останавливается только движение. Раньше `loop()` Telega4 при этом выходил целиком.
3. Сигнал «стоп» от HC-SR04 раньше шёл на вывод 27 для платы управления, но Telega4 его не читал. Теперь в режимах COM / AUTO / CAL_DIST препятствие или потеря цели (LOST) останавливает тележку программно, а после CLEAR она едет дальше. После LOST движение возобновляется только командой `N R`. В ручном режиме RC остановка не вмешивается.
4. Калибровка IMU теперь хранится в `Preferences` (раздел `imu`), а не в EEPROM. **На объединённой плате выполните один раз `N C`** на ровной поверхности.
5. На время блокирующих операций датчиков (`N C` — 2 с, `N X`) тележка останавливается.
6. `sensors.py` обновлён: служебные команды отправляются с префиксом `N`, лишние строки он пропускает.

## Расхождения, найденные в исходниках

- В шапке sensor_node указано SDA 21 / SCL 22, TRIG 32 / 33, ECHO 34 / 35, XSHUT 4 / 13 / 25 / 26, а в коде — SDA 22 / SCL 21, TRIG 2 / 25, ECHO 26 / 34, XSHUT 33 / 4 / 13 / 32. В Telega5 взяты значения **из кода**. Проверьте, что разводка совпадает с ними.
- TRIG A на GPIO 2 в sensor_node совпадал с тумблером 2 RC в Telega4. На одной плате так нельзя, поэтому TRIG A перенесён на GPIO 18.
